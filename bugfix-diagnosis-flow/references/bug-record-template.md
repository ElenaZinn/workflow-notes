# Bug 复盘记录模板

修完一个 bug 后花几分钟填完，攒起来就是可检索的经验库。前六栏是记录，**最后两栏才是复利来源**。

```text
# Bug 记录：<一句话现象>

日期：YYYY-MM-DD
优先级：阻断性 / 体验性
影响范围：<谁受影响、多严重>

## 问题定格
- 现象：
- 复现条件：必现 / 偶现（已知触发条件：）
- 最小复现路径：

## 证据
- 用了什么手段（日志 / Profiler / 抓包 / Trace / 二分 / 埋点）：
- 关键证据：
- 排除掉的假设：

## 根因
- 根因（一句话，写到机制层，不是表象）：
- 时序图 / 调用链偏离点：

## 改动点
- 改在哪里：
- 影响半径：
- 为什么是这里：

## 方案与结果
- 改了什么：
- 验证方式：
- 结果：解决 / 部分解决 / 未解决

## 未解决时的排查记录
- 是改动没生效、还是根因判断错了：
- 换的假设：
- 最终怎么收的（升级 / 临时缓解 / 待办）：

## 失效模式归类
- 这次属于哪一类（根因误判 / 回归副作用 / 改动未生效 / 复发 / 过度修改）：

## 一句话判断经验
- 下次遇到 <X 现象> 时，我应该先怀疑 <Y>。
```

## 填写要点

- 「排除掉的假设」别省。它防止下次重复排查同一条死路，和找到根因一样有价值。
- 「卡住的地方」写具体现象，不要写「不熟」「多看文档」这类空话。
- 「失效模式归类」用 SKILL.md 里的那张表，同一类反复出现，说明是流程问题不是个案。
