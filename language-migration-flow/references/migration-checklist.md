## 二、CI gate 与禁止规则（对应第 4 步）

**原则**：规则要落到机器上，不靠自觉；gate 被绕过要有告警。

### Rust 侧示例

```bash
# CI gate（任一失败即阻断）
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

### 建议的禁止规则（按项目增删）

| 禁止 | 理由 | 落地方式 |
| --- | --- | --- |
| 新代码使用 `unsafe`（除非带说明） | 安全边界要显式 | `clippy` denylist + 评审 checklist |
| 处理外部输入时用 `unwrap` / `expect` | 会 panic | lint 规则 + 评审 |
| 核心层引入平台依赖 | 破坏可移植与可测 | 依赖检查 / 分层 lint |
| 跨层直接依赖 | 破坏分层 | 模块依赖检查 |
| 直接 `println!` 当日志 | 无级别、无法关闭 | lint + 评审 |

### gate 绕过告警

- 允许例外，但**例外必须留痕**：谁批的、为什么、什么时候到期。
- 定期统计绕过次数；次数上升说明规则不合理，而不是人不行。

## 三、阶段计划与验收 checklist（对应第 5、8 步）

```text
## 阶段计划表

| 阶段 | 目标 | 范围 | 验收标准 | 回滚方式 | 状态 |
| --- | --- | --- | --- | --- | --- |
| P0 | 搭 gate + 锁定契约 |  | gate 全绿、契约文档完成 | 无（纯新增） |  |
| P1 | 非核心模块搬迁 |  | 对照测试通过 | 切回原实现 |  |
| P2 | … |  |  |  |  |
```

### 单个阶段的准出 checklist

```text
□ 范围与目标与阶段计划一致，没有顺手扩大
□ gate 全绿（fmt / clippy / test）
□ 对照验证通过（同输入，双端输出一致）
□ 行为差异已写入变更记录
□ 可回滚（能退回上一个可用状态）
□ 旧 bug 只记录未顺手修
```
