# 代码 / 语言迁移工作流

## 这套流程解决什么

迁移常见的两种失败：

- **全量重写**：工期失控，还把原有的对外契约和行为语义弄丢了。
- **局部乱改**：改一处崩一片，没有验收标准，也没有回滚点。

这套工作流的原则：**先锁定不可变契约，再做增量替换；每处改动留痕，每个阶段有验收、有回滚点。**

## 八个动作

### 1. 现状盘点：先量，再写

- 盘点要迁的范围：文件、模块、依赖、调用方、测试覆盖情况。
- 记录现状行为，作为验收基线：接口、数据结构、边界条件、错误处理、精度与时序。
- 迁移中发现的旧 bug **只记录，不顺手修**（否则无法区分是迁移引入还是本来就有）。

**产出**：迁移范围清单 + 行为基线。

### 2. 写迁移规范（spec）

- 写清：迁什么、**不迁什么**、为什么、完成标准是什么。
- 明确边界：哪些留在原语言，哪些跨语言边界（FFI/桥接）怎么走。
- 必须能被他人复核——写给自己看的 spec 不算数。

**产出**：一份迁移规范。模板见 `references/migration-checklist.md`。

> 真实案例参考：WanAndroid-rust 里的 `porting-guide` 与 `binding-contract` 就是这个角色的产物——契约先行，实现后补。

### 3. 锁定不可变契约

- **对外接口**：函数签名、错误码、协议。
- **数据结构与序列化格式**。
- **行为语义**：错误处理方式、精度、时序、幂等。
- **跨语言 ABI**：函数签名与所有权约定。例如从手写 C ABI/JNI 迁到 UniFFI 时，**先把契约锁死，再换实现**。

**规则**：契约要动，必须先出变更记录并整体重算影响，不能顺手改。

### 4. 搭建 CI gate 与禁止规则

迁移最大的风险是「说好的规则没人执行」。所以要把规则落到机器上。

- **CI gate**：格式化、静态检查、测试全部通过才允许合入。例如 Rust 侧：
  - `cargo fmt --check`
  - `cargo clippy -- -D warnings`
  - `cargo test`
- **禁止规则**：把不想要的写法写死，例如「新代码禁 `unsafe`（除非带说明注释）」「禁 `unwrap` 处理外部输入」「禁核心层引入平台依赖」「禁止跨层依赖」。用 lint 规则 + 评审 checklist 双保险。
- **checklist**：每个阶段的准入清单与准出清单。

**关键**：gate 被绕过时必须有告警。没有告警的 gate 形同虚设。

具体配置示例与清单见 `references/migration-checklist.md`。

### 5. 划分阶段

- 顺序从**低风险 / 非核心**到**高风险 / 核心**。
- 每个阶段只做一件事，能单独跑、单独测、单独撤回。
- 阶段太大 = 出问题无法定位 + 无法回滚。

**产出**：阶段计划表（目标、范围、验收标准、回滚方式）。

### 6. 变更留痕

- 记：改了什么、为什么、影响谁、怎么验证。
- **跨语言边界的行为差异必须记录**——这是整次迁移最容易踩坑的地方。

### 7. 先建测试基线，再重构结构

- 在重构结构之前先把测试或对照实现补上。结构定下来之后就不好查了。
- 双端并存期间做**对照验证**：同一输入，两边输出是否一致。差异就是风险点。

### 8. 阶段验收与返工

- 出验收结论：达标 / 部分达标（差什么）/ 返工。
- 不达标先退回到上一个可用状态，再缩小范围重做，不要在坏状态上继续叠加。

## 失效模式

| 失效 | 表现 | 怎么退 |
| --- | --- | --- |
| 全量重写 | 工期失控、行为基线丢失 | 改为增量替换：锁定契约，分阶段 |
| 局部改动连锁 | 改一处崩一片 | 回到不可变契约清单，重新评估影响 |
| 测试基线缺失 | 结构定下后才发现问题 | 补对照测试，小步回退 |
| gate 被绕过 | 禁的写法照样进来，且无告警 | 给 gate 加绕过告警与审计 |
| 双端不一致 | 迁移后行为悄悄变了 | 对照验证，差异写入变更记录 |
| 阶段过大 | 出问题定位不了，也回滚不了 | 拆小，每阶段可独立验收 |

## 边界

- 迁移中发现的旧 bug 默认只记录、不顺手修；要修就单独立项。
- 不假设本机能跑通一切。现实约束（例如本机磁盘装不下 Android SDK/NDK）下，优先零本地占用方案：CI artifact、Codespaces、devcontainer。像 `cargo fmt/clippy/test` 这类只需要语言工具链的校验，可以在本地跑，不必打 APK。
- 不为「看起来改得彻底」而扩大范围。目标是可用且可验证，不是全新。
